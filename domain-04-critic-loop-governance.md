# Domain 04: The Epistemic Critic Loop & Governance Mechanics
**Governed Multi-Agent Decision-Support Substrate (GMADSS) Specification**

## 1. Executive Summary & Purpose
The **Epistemic Critic Loop** serves as the primary adversarial safety mechanism and internal "court of appeal" within the Governed Multi-Agent Decision-Support Substrate (GMADSS). Standard large language models lean heavily toward conversational agreeableness, stylistic overconfidence, and narrative smoothing—frequently concealing data omissions or forcing artificial consistency when encountering ambiguous, flawed, or fragmented data inputs.

The Critic Loop directly counteracts this behavioral bias by functioning as an independent, non-generative auditing layer. It rigorously scrutinizes all candidate payloads generated by the Synthesis Worker Tier against hardcoded legal, procedural, and factual system constraints before any advisory output can transition across the security boundary to the human professional.

---

## 2. Core Governance Mechanisms

### 2.1 Adversarial Audit Mechanics
* **Decoupled Evaluation Environments:** Critic agents operate inside fully isolated context runtime environments, entirely separated from the generative and synthesis worker tasks that compiled the draft response.
* **Deterministic Verification Framework:** The Critic Loop evaluates draft payloads against three non-negotiable structural criteria:
  1. **Source Citation Grounding Verification:** Cross-checks every generated text anchor to ensure that cited rules, policy sections, and statutory definitions exist verbatim within the provided source index.
  2. **Hierarchy Integrity Audit:** Enforces compliance with the baseline rule that Level 1 Legislation strictly overrides Level 2 Policy, which strictly overrides lower-level manuals and operational guides.
  3. **Narrative Closure Prevention:** Validates that the generative substrate has not filled in missing historical parameters, invented missing details, or smoothed over conflicting policy parameters instead of raising an authority exception.

### 2.2 The "Contested" State Enforcement
When primary sources or operational directives contain conflicting guidance (e.g., an outdated, un-updated localized manual directly contradicting a newly enacted statutory regulation):
* The Critic Loop **unconditionally rejects** any attempt by synthesis workers to harmonize, average, or smooth over the contradiction.
* It halts standard output compilation and forces the runtime layer to render an explicit, high-priority **Contested Authority Marker**. This marker details the precise friction point between the conflicting files, ensuring the human professional retains complete situational awareness and accountability.

## 4. Governance Protocol & Safety Invariants

### 4.1 The Zero-Execution Safety Invariant
The Critic Engine verifies that no generated response payload contains autonomous transactional prompts, mock legal orders, direct application execution strings, or database command blocks. The detection of any actionable code snippet or un-authorized operational instruction triggers an immediate, un-conditional session termination to maintain strict advisory-only posture.

### 4.2 Hallucination Penalization Error States
If a synthesis worker introduces an external clause, un-indexed statutory code, or undocumented practice assumption, the Critic Loop generates a formal exception block:
```json
{
  "audit_status": "REJECTED",
  "error_classification": "UNGROUNDED_HALLUCINATION",
  "violation_source_agent": "worker-synth-clarity",
  "enforced_remediation": "TERMINATE_THREAD_AND_FORCE_REPARSE_TEMP_0"
}
```
The active output payload is discarded, and the system re-runs the data stream at a hard-locked temperature state of `0.0`.

### 4.3 Human Oversight Provenance Header
Every advisory output passed by the Critic Loop securely prepends an immutable governance record block to ensure clear systemic accountability:
